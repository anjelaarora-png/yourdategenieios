# Waitlist Popup — Diagnosis & Fix (2026-06-18)

The exit-intent popup ("Wait. Before you go — be among the first") lives **only on the live WordPress site** (it's not in the repo). It has **two real bugs** plus one cosmetic one.

## What's broken — ranked

| # | Problem | Root cause | Impact |
|---|---------|-----------|--------|
| 🔴 1 | **Emails don't save** | Firestore rule for `waitlist` requires `fullName` + `city`, but the popup only collects **email** → every write is rejected | Losing 100% of popup signups |
| 🔴 2 | **Firebase never initializes** | On the live page `firebase.apps.length === 0` — `initializeApp()` never runs, so the Firestore write throws before it even reaches the rules | Losing 100% of popup signups |
| 🟡 3 | **`—` shows as literal text** | Escaped Unicode was pasted as plain text into WordPress instead of the real "—" character. Page-wide: **162 instances** | Looks broken / off-brand |

## Fix 1 — Security rules (DONE in repo)

`firestore.rules` now requires only `email` + `source` + `createdAt`, and validates `fullName`/`city` **only if present**. The full waitlist form still works; the email-only popup now passes.

**You deploy it:**
```bash
firebase deploy --only firestore:rules
```

## Fix 2 — Add the missing Firebase init + correct write

Replace the popup's `<script>` with this. (The Firebase **web config values are public**, safe in client code — copy them from Firebase Console → Project settings → Your apps → Web app.)

```html
<script>
(function () {
  var firebaseConfig = {
    apiKey: "YOUR_FIREBASE_API_KEY",
    authDomain: "your-date-genie.firebaseapp.com",
    projectId: "your-date-genie",
    storageBucket: "your-date-genie.appspot.com",
    messagingSenderId: "710263961293",
    appId: "YOUR_FIREBASE_APP_ID"
  };
  // THIS is what was missing — apps.length was 0 on the live page:
  if (window.firebase && !firebase.apps.length) firebase.initializeApp(firebaseConfig);
  var db = firebase.firestore();

  var form  = document.getElementById('ydg-popup-form');
  var input = document.getElementById('ydg-popup-email');
  if (!form) return;

  form.addEventListener('submit', async function (e) {
    e.preventDefault();
    var email = (input.value || '').trim();
    if (!/.+@.+\..+/.test(email)) { input.focus(); return; }
    var btn = form.querySelector('button[type=submit]');
    if (btn) { btn.disabled = true; btn.textContent = 'Saving...'; }
    try {
      await db.collection('waitlist').add({
        email: email,
        source: 'exit_popup',
        createdAt: firebase.firestore.FieldValue.serverTimestamp()
      });
      form.innerHTML = '<p style="text-align:center;margin:0">You\'re on the list — check your inbox.</p>';
    } catch (err) {
      console.error('Waitlist save failed:', err);
      if (btn) { btn.disabled = false; btn.textContent = 'Save my spot'; }
      alert('Something went wrong — please try again.');
    }
  });
})();
</script>
```

**After deploying, verify it works:** open the site, submit a test email, then check Firebase Console → Firestore → `waitlist` for a new doc with `source: "exit_popup"`.

> ⚠️ If you enabled **App Check / reCAPTCHA** in Firebase (there's a `VITE_RECAPTCHA_SITE_KEY` in `.env`), writes will be blocked until the popup also initializes App Check — or until App Check enforcement is turned **off** for Firestore while pre-launch. Check Firebase Console → App Check.

## Fix 3 — The literal `—` text

In the popup copy, replace the escaped codes with the real characters:

| Replace this literal text | With |
|---|---|
| `—` | — (em dash) |
| `’` | ' (apostrophe) |
| `…` | … (ellipsis) |

Corrected popup copy:
- Headline: **Wait. Before you go — be among the first.**
- Bullet: **Free *30 Date Nights* guide — sent the moment you join**

⚠️ **Bigger issue:** the same `—` problem appears **162 times across the whole homepage**, not just the popup. That means a whole block of homepage content was pasted as escaped code instead of rendered text. Recommend re-pasting that homepage section as actual rendered HTML (real "—", real emoji) rather than the `\uXXXX` source — happy to prep that block next.
